# Chrome起動時のキーリング解除を省く

この構成では、自動ログインを使い、「ログイン」キーリングのパスワードを空にする運用を選択しています。変更には現在のキーリングパスワードが必要です。この操作は初回だけGUIで行います。以後のセットアップ再実行ではパスワードを変更しません。

```bash
bash install.sh --only chrome-keyring --apply
```

1. 起動した「パスワードと鍵」（Seahorse）のサイドバーを表示する。
2. 「パスワード」の下の「ログイン」（Login）を右クリックし、「パスワードの変更」を選ぶ。
3. 現在のキーリングパスワードを入力する。
4. 新しいパスワード・確認欄を**両方空のまま**続行する。
5. 暗号化しない旨の警告を確認して確定する。
6. Chromeを完全に終了し、ログアウト→ログイン後に起動して確認する。

`login.keyring` を削除する必要はありません。既存の保存情報を保ったまま変更できます。「ログイン」以外のキーリング名が解除画面に表示される場合は、そのキーリングの設定を確認してください。

**空パスワードにすると、このキーリングの内容はパスワードで暗号化されません。** 他アプリの保存情報にも影響します。ディスク暗号化やOSのファイル権限とは別の保護です。スクリプトは秘密情報やキーリングをバックアップ領域へコピーしません。

現在のパスワードを忘れた場合、この方法では変更できません。キーリングを削除すると保存済みの秘密情報やChromeの暗号化情報に影響するため、自動削除・リセットは用意していません。

## 通常のパスワードログインへ戻す場合

同じ画面でキーリングのパスワードをUbuntuのログインパスワードと同じ値に変更します。GDMの通常のパスワードログインではPAM経由で自動解除できます。自動ログインや指紋ログインでは、解除用のパスワードがログイン時に渡らないため、追加の解除が必要になる場合があります。

`--password-store=basic` はChromeのみの別の回避策ですが、Chrome側の保存パスワードが平文ストアになるため、この構成では使用しません。

参照: [GNOMEのパスワード変更](https://help.gnome.org/seahorse/keyring-update-password.html)、[PAMの自動解除](https://wiki.gnome.org/Projects/GnomeKeyring/Pam)、[パスワードなしログインと解除](https://wiki.gnome.org/Projects/GnomeKeyring/RunningDaemon)、[Chromiumの保存方式](https://chromium.googlesource.com/chromium/src/+/HEAD/docs/linux/password_storage.md)。
